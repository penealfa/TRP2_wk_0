# Failures

What broke, what I tried, and what fixed it (or how I worked around it). Quota, memory,
consistency and language problems all belong here. Link the `runs.jsonl` lines
(`status != "ok"`) that show each one.

| # | When | What broke | Evidence | What I tried | Resolution |
|---|---|---|---|---|---|
| F0 | Day 1, building the skeleton | Narration cleaning hung forever on a take with no silence at all | ffmpeg process stuck at 0% CPU in `tests/test_caching.py` | Isolated the filter chain: trim alone OK, loudnorm alone OK, `areverse` + `loudnorm` in one graph hangs on FFmpeg 6.1.1 | Split into two FFmpeg passes (trim, then level); added `-nostdin` to every call so FFmpeg never waits on the terminal |
| F1 | Day 1, narration | Gemini TTS returned HTTP 429 after 7 lines (`generate_content_free_tier_requests`, limit 10) | `runs.jsonl` narration s08–s10, `status: retryable_error`, 2026-11-26T04:57 | Built-in retries (3 attempts, backoff) weren't long enough for the quota window | Waited ~6 min and reran `make narration`; the cache skipped the 9 finished lines, so only s10 and s11 were called (2026-11-26T05:03, `ok`) |
| F2 | Day 1, keyframes | Cloudflare Workers AI rejected the API token (HTTP 401, then `code 1000 Invalid API Token` from `/user/tokens/verify` and `/accounts/<id>/tokens/verify`) | `runs.jsonl` smoke, `@cf/black-forest-labs/flux-2-klein-4b`, `fatal_error` | Checked for whitespace in `.env`; tried the account-scoped verify endpoint | Created a new token; `/user/tokens/verify` returned "valid and active" and the keyframe stage ran (user-owned tokens verify only on the `/user/` endpoint, not `/accounts/<id>/`) |
| F3 | Day 1, radio cut | Radio cut came out 94.7 s, outside the 60–90 s brief: TTS reads Amharic slower than the planned 2.3 words/s, so s03, s04, s07 and s08 ran past their planned length | `[assemble] WARNING: 94.7s is outside the 60-90 s brief` | Cutting words would weaken the script | Trimmed the padding on shots with short lines (s01 7→6.2, s02 6→4.5, s05 6→5, s09 7→6, s10 5→4, s11 8→6.5): 88.5 s |
| F4 | Day 1, keyframes | Cloudflare's output filter flagged s01 (`code 3030`, "Your output has been flagged"); the stage misread the message (it mentions "input image") as an image-field error, fell back to text-only, and was flagged again | `runs.jsonl` keyframes s01 `fatal_error` | A different seed for the same prompt | `keyframes._generate` now retries a flagged output with seed+1..+3 (logged as `seed_offset`) and never treats a flag as an image-field error; seed 102 passed. Test: `test_flagged_output_retries_next_seed_without_text_only_fallback` |
| F5 | Day 1, keyframes | Character consistency: FLUX.2 klein copies the *layout* of the reference image, not just the character. A three-panel wolf sheet turned s02 and s06 into three-panel images; a full-body figure on blank ochre turned close-ups (s03, s10) into full-body figures on blank ochre | contact sheets from the first two keyframe runs | Three reference framings across three runs | `characters[].ref_framing`: Peneal as an ornamental head-and-shoulders portrait, the wolf full-body against a dark night background, matching the scenes they appear in. Also the Peneal description had been guessed ("clean-shaven, no glasses"); corrected from the reference photo, which regenerated only his 6 shots + sheet |
| F6 | Day 1, Wan 2.2 on Kaggle T4 | CUDA out of memory at denoising step 0 for s02, and again on both smaller fallback sizes (640² x49, 512² x49, 512² x33): peak 15.45 GB of 14.56 GB. Model load alone took 231 s | `runs.jsonl` shots s02 `status: oom`, `peak_vram_gb: 15.45`, `gpu: Tesla T4` | The 5B transformer (~10 GB bf16) stays resident under `enable_model_cpu_offload()`; after the first OOM the hooks left it on the GPU, so the smaller retries started already full | Notebook now uses `enable_sequential_cpu_offload()` (layer streaming) and frees hooks after an OOM; rerun with s02 only. **Result:** s02 succeeded (640x640, 49 frames, peak VRAM 6.93 GB) but took 2,499 s (41.6 GPU min) plus 227 s model load, twice the 20-minute budget I set in advance. Decision: one Wan clip (s02, the wolf's arrival), and the other 10 shots keep the pan-and-zoom fallback. 11 shots x 42 min would be 7.6 GPU hours of the 30 h weekly quota, with no room for retries. Afterwards the keyframes were regenerated with the style wording changed to "traditional Ethiopian painting style", which invalidated the s02 clip (its cache key includes the keyframe hash); I chose not to repeat the 42-minute run, so the final films use pan-and-zoom for all 11 shots |
| F7 | Day 1, ACE-Step 1.5 on Kaggle | The music kernel failed in 48 s: `ERROR: Package 'ace-step' requires a different Python: 3.13.16 not in '<3.13,>=3.11'`, then `ModuleNotFoundError: No module named 'acestep'`; `flash-attn` also fails to build (no nvcc) | Kaggle kernel log for `heritage-short-acestep` v2 | `pip install` on the default Python 3.13 image | Notebook builds a Python 3.12 venv with `uv`, drops `flash-attn` from the requirements, and runs generation as a subprocess in that venv (with `MPLBACKEND=Agg`: the notebook's inline matplotlib backend does not exist there); third failure: all 3 candidates ended `Generation produced NaN or Inf latents (dtype=float16)` after 9-11 s, because the T4 is pre-Ampere and fp16 overflows; the error text suggests `ACESTEP_DTYPE=float32`, but I read the source and that variable is only in the message, not implemented (a second run with it set still logged `dtype=torch.float16`); fixed by patching the one `self.dtype = torch.float16` line in `init_service_orchestrator.py` to float32 in the notebook's install step, and dropping int8 quantization. The repo is cloned to `/tmp` because the original clone in `/kaggle/working` made `kaggle kernels output` download ~1 GB and stall |
