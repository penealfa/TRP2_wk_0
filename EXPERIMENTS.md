# Experiments

Each entry: **hypothesis → change → result**, with evidence (`runs.jsonl` lines, seeds, file names,
test notes) and the **decision** it led to. Fourteen entries are completed (E2, E7, E8 and E9 to E19).
Five of the original hypotheses (E1, E3, E4, E5, E6) were **not run**, and the table says so with the reason,
instead of leaving them blank.

Where to look: `runs.jsonl` has one line per model call (stage, item, seed, latency, status);
`FAILURES.md` has the matching failure write-ups; `experiments/e8_ducking.py` and its output
`experiments/e8_ducking.json` reproduce E8. Stage names in `runs.jsonl`: `keyframes`, `narration`,
`shots` (Wan), `music`, `blender_script` and `blender` (the optional layer).

## Completed experiments

| # | Hypothesis | Change | Result (evidence) | Decision |
|---|---|---|---|---|
| E2 | Passing a character reference image to FLUX.2 klein keeps Peneal and the wolf recognisable across shots | Every keyframe call gets the reference image of each character in the shot (`keyframes` calls in `runs.jsonl` log `refs: 1` or `refs: 2`) | Yes for identity: Peneal's face, glasses and beard carry across s01, s03, s05, s08, s10 and s11 (contact sheet, last run). But the model also copies the reference's layout (see E9). The text-only baseline was **not** run, so this shows consistency, not improvement over text | Keep reference conditioning; design the reference like a shot (E9) |
| E7 | Of three ACE-Step candidates, the one with the least energy in the speech band (300-3400 Hz) will sit best under the Amharic narration | Generated c1, c2, c3 (seeds 27, 28, 29, same caption, Kaggle T4, `music` lines in `runs.jsonl`: 24.1 s, 21.8 s, 22.1 s each) and measured the speech-band RMS relative to total RMS with FFmpeg | c1 -2.38 dB, c2 -2.87 dB, c3 **-4.26 dB** (levels within 1 dB of each other overall). The three differ only by seed, so this compares takes, not captions | Chose c3 (`music.chosen_reason` in `storyboard.json`); I then listened to the mix under the narration and approved it |
| E8 | The brief's ducking settings (threshold 0.02, ratio 6, attack 300 ms, release 1500 ms) are a good start | Ran the mix's own sidechain filter on the real score and narration with three settings and measured the score alone inside speech and in gaps (`experiments/e8_ducking.py`, results in `experiments/e8_ducking.json`) | A (default): score **-9.9 dB** under speech, -1.8 dB in gaps (vs undipped). B (threshold 0.01, release 800 ms): -11.7 dB under speech, -1.1 dB in gaps. C (ratio 12): -10.6 dB, -1.9 dB. So B ducks 1.8 dB deeper and recovers 0.8 dB faster; raising the ratio does little. Measured only, no blind listening | Kept A: the difference is small, I had already approved the mix by ear, and changing it would re-mix both films |
| E9 | A multi-panel reference sheet is the best reference for FLUX.2 (the brief's suggested practice) | Three framings in three runs: (1) a three-panel sheet for both characters; (2) one full-body figure on a plain background; (3) per-character `ref_framing`: head-and-shoulders portrait for Peneal, full-body on a dark night background for the wolf | (1) s02 and s06 came back as three-panel images. (2) close-ups s03 and s10 became full-body figures on blank ochre. (3) every shot kept its intended framing. Cost: 55 successful keyframe calls for 13 final images (`keyframes` in `runs.jsonl`; `ref_peneal` generated 5 times, `s01/s03/s05/s08/s10/s11` 5 times each) | Adopted `characters[].ref_framing` (`FAILURES.md` F5); a reference must match the scenes it will appear in |
| E10 | Because stages are cached by input hash, one edit regenerates only what depends on it | Three real edits, each followed by a full `pipeline.run` | (a) Changing the s09 line: 1 call, `narration` s09 (`runs.jsonl` run `20261126T101559Z-e6dc9f`), everything else `cached`. (b) Correcting Peneal's description: `ref_peneal` and his 6 shots regenerated; the 3 wolf-only shots (s02, s04, s06) did not. (c) Changing the style wording: all 11 shots plus both sheets, as expected. The per-item generation counts in E9 show the pattern: s07 and s09 (no character references) were generated only twice in total | Property holds; it is the walkthrough demo. Also covered by `tests/test_caching.py` |
| E11 | Sequential CPU offload lets Wan 2.2 TI2V-5B fit a 15 GB T4 where model offload does not | Same job (s02, 640x640, 49 frames, 30 steps, seed 102) with `enable_model_cpu_offload()` and then `enable_sequential_cpu_offload()` | Model offload: out of memory at denoising step 0, peak 15.45 GB, and the retries at 640² and 512² also failed because the model stayed on the GPU (Kaggle log; this first failed log was not imported into `runs.jsonl`). Sequential offload: success, peak **6.93 GB**, 2,499 s (41.6 GPU min); the s07 clip took 2,258 s (`shots` lines in `runs.jsonl`) | Use sequential offload and free the hooks after an OOM; budget about 40 GPU minutes a clip, so only 2 clips were made (`FAILURES.md` F6) |
| E12 | ACE-Step 1.5 produces NaN latents in float16 on a pre-Ampere T4, and float32 fixes it | Three Kaggle runs: default dtype; then `ACESTEP_DTYPE=float32`, which the error message suggests; then the notebook patches `self.dtype = torch.float32` in `init_service_orchestrator.py` | Default dtype: 3 of 3 candidates failed with "NaN or Inf latents (dtype=float16)" after 9-12 s each. With `ACESTEP_DTYPE=float32`: 3 of 3 failed the same way (the log still says float16; the variable is only in the error text, not implemented). Patched dtype: 3 of 3 ok, about 22 s each (`music` lines in `runs.jsonl`). The failed attempts are in the Kaggle kernel logs, not imported into `runs.jsonl` | Patch the dtype; do not trust an error message's suggested fix until a run proves it (`FAILURES.md` F7) |
| E13 | Cloudflare's output filter flags are seed-dependent, so the next seed passes | After a flag, `keyframes._generate` retries with seed+1 (up to +3) and logs `seed_offset` | 6 flagged calls (`keyframes`, `status: fatal_error`, code 3030): s01 seed 101 four times, s08 seed 108, s10 seed 110. Every item passed on the next seed (102, 109, 111; 5 recoveries logged with `seed_offset: 1`, never needed +2). The earliest s01 flags came before the retry code existed and stopped the run | Keep the seed retry; flags do not need prompt changes (`FAILURES.md` F4; `tests/test_keyframes_p2.py`) |
| E14 | Dropping "Orthodox church" from the style prompt changes the look little | Changed `style.style_block` to "traditional Ethiopian painting style" and regenerated all 11 keyframes (seeds unchanged, aside from retries) | The painted look held; s07 and s08 got better (a clean panel of makers; Peneal at the end of a line of makers). Flags rose from 1 of 11 shots to 3 of 11 (s01, s08, s10), too small a sample to call a trend. About 3 minutes, $0 | Adopted; but it made the old Wan clip stale because its cache key includes the keyframe, so s02's clip was not used (E11, `FAILURES.md` F6) |
| E15 | A narration pace of 2.3 words per second fits the 60-90 s brief | Planned the film at 2.3 words/s; built the radio cut; measured | Real narration is 73.2 s for 96 words, about **1.3 words/s** (Amharic TTS, calm style). The first radio cut ran 94.7 s, outside the brief. Trimming hold time on six short-line shots (s01, s02, s05, s09, s10, s11) gave 88.5 s without cutting words; the final films are 89.2 s | Plan from measured narration time, not words per second (`FAILURES.md` F3) |
| E16 | Rendering each keyframe in Blender (the picture on a plane displaced by its own brightness, with a camera move) gives depth that beats pan-and-zoom | Built `pipeline/blender_layer.py`; rendered all 11 shots (1080x1080, EEVEE, RTX 5060) | Renders ran 68 to 308 s per shot (median 148 s; `blender` lines in `runs.jsonl`). The depth guess left wavy, squiggly lines in the painted outlines (my judgement), and early renders showed black edges until I added camera limit constraints | Not used in the final films; kept as a documented optional layer (`FAILURES.md` F8) |
| E17 | A Cloudflare text model is a better script writer than Gemini for the Blender layer, on the day | Asked Gemini first (a four-model chain), then switched the default to Cloudflare `@cf/qwen/qwen2.5-coder-32b-instruct` | Gemini: 31 calls, **0 succeeded**, every one HTTP 503 (gemini-3.8-flash 17, 3.7-flash 6, 3.5-flash 4, flash-latest 4; `blender_script` lines). Cloudflare: 16 of 16 ok, median **36 s** (30-50 s) per script; one script failed in Blender (s08) and the model repaired it on the second try. The 503s may have been temporary | Cloudflare is the default writer (`HS_BLENDER_LLM=gemini` switches back) |

## Not run

| # | Hypothesis | Why it was not run |
|---|---|---|
| E1 | My own recorded voice will land better with the audience than Gemini TTS | I chose Gemini TTS for both characters early in the project, so there is no recorded take to compare against and no blind listening test. I am not claiming a result |
| E3 | Square 640 px Wan clips cropped to both aspects look acceptable versus native 16:9 | Only square clips were rendered. They cropped cleanly to 9:16 and 16:9 in the films, but a native 16:9 render was never made, so there is no comparison |
| E4 | 480p drafts cost less GPU time than 720p without losing motion | Every clip ran at 640x640, 49 frames (about 40 GPU minutes); 720p was never run because the first 640 clip already used twice the time budget |
| E5 | bf16 on a T4 avoids the black or NaN frames fp16 gives for Wan | `WAN_FP16=1` was never run; bf16 worked first time once memory was fixed. The same question for ACE-Step was run (E12) |
| E6 | Shorter, motion-only Wan prompts give fewer artifacts | Not run: each Wan comparison would cost another 40 GPU minutes of the 30 GPU hours weekly quota |
